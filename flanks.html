Four ways to show the same flanks

I have guessed twice at what is wrong with the flanks and been wrong twice, so here are the plausible presentations of the same data instead of a third guess. The element alignment is byte-identical in all four — only the flanks differ.

A FASTA alignment is rectangular, so a copy with a short flank has to be padded somewhere. The variants differ in how much flank is shown and whether padding happens at all.

The four variants

A — flush. Each copy's flank is de-gapped and butted hard against the element; the panel is as wide as the longest copy's flank, and shorter copies are padded on the outer side. This is what every review alignment has been. Its failure mode: one copy with a long flank pads all the others, so the panel fills with gaps.

B — trimmed. Same, but the width is capped so the panel is at most 25 % gaps. Long copies get cut.

C — short. Every flank cut to at most 30 bp. Almost no padding; you see only the sequence immediately outside the element, which is where the boundary shows itself.

D — ragged. No padding at all. Each copy's flank is written at its own length, so the rows have different lengths. This is the only genuinely unaligned presentation — and it is not a valid alignment file, so the viewer may refuse it or render it oddly. That is worth knowing either way.

Which of these is what you want to look at? Or is none of them it?
