What SubFam does with the loci left over after the last full chunk

SubFam cuts the ordered loci into chunks of 50 and, since the 2026-09-05 repo version, deletes the final chunk if it has fewer than 50. The deleted loci are not a random sample: they are the end of the guide-tree order, so the same group is removed again and again. Keeping the short chunk with a consensus threshold scaled to its size loses nothing and gives the purest consensus. Overlapping the last 50 loci mixes the tail with its neighbour and counts about 25 loci twice.

The patched script

Tested on KIT with 112 loci (SubFam's chunk size 50). Nothing is installed anywhere; this is a proposal for the SubFam repository.

SUBFAM_LAST=keep      bash SubFam.last_chunk.sh loci.fa      # default: chunks 50 / 50 / 12, last consensus threshold scaled
SUBFAM_LAST=balanced  bash SubFam.last_chunk.sh loci.fa      # chunks 38 / 37 / 37, nothing lost or doubled
SUBFAM_LAST=drop      bash SubFam.last_chunk.sh loci.fa      # chunks 50 / 50 (the 2026-09-05 behaviour)

The consensus threshold becomes 36 % of the chunk's loci (cons -plurality 18 for 50 loci, so full chunks are unchanged; 4 for 12; never below 2). A one-locus leftover is skipped because MAFFT needs two sequences. With nothing left over the output matches the original up to MAFFT's own run-to-run variation: the original SubFam gave different consensus files when run twice on the same input.

Recommendation

Keep the short chunk and scale its consensus threshold (keep). If every chunk must have about the same size, use the balanced split, not the overlap: purity is the same as the overlap and no locus is counted twice.

How this was tested, and what it cannot show

Loci come from the 600 ccr chunk banks (50 loci each) of the SubFam run on KIT. The group of a locus is the group you peeled its chunk into (351 of 600 chunks, 17,550 loci, 7 groups), so labels are chunk-level, not per locus. Each replicate samples N loci from the chosen groups, orders them with mafft --retree 0 --reorder as SubFam does, cuts chunks of 50 and applies each option to the leftover. Results: 26 sample sets, 5 to 6 replicates each. A per-locus truth was not available for another species (the teu truth file is chunk-level with repeated names). Purity is higher for small chunks by construction, so options are compared within the same leftover size.
